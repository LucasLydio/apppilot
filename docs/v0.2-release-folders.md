# v0.2 Release Folder Rollback

Goal: make rollback safer than `git reset --hard` by running apps from immutable release folders and switching a `current` symlink.

## Target Layout

```text
~/apps/users-api/
  repo/                 Git working tree used for pull/test/build
  releases/
    20260819T120000Z/
    20260819T123000Z/
  current -> releases/20260819T123000Z
  shared/
    .env
```

## Rules

- Do not migrate an existing app silently.
- Require a dry-run plan before enabling release-folder mode.
- Keep `.env` in `shared/.env` and link/copy it into each release.
- Deploy builds in `repo/`, copies the build output into a timestamped release, updates `current`, then restarts the app.
- Rollback switches `current` to the previous known-good release and restarts the app.
- Keep the existing Git-reset rollback for simple v0.1-style apps until the app is migrated.

## Planned Commands

```bash
apppilot releases plan <app>
apppilot releases enable <app>
apppilot releases list <app>
apppilot releases rollback <app>
apppilot releases rollback <app> --to <release-id>
```

## Open Questions

- PM2 apps can run from `current/<entrypoint>` after migration.
- Compose apps may need generated Compose project paths or careful bind-mount handling.
- Backups should run before the first migration.
